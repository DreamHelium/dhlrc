# 区域加载顺序

一个文件里有多个区域时，文件本身往往没有有意义的顺序：写文件的程序可能把它们放在
哈希表里，所以每次载入的顺序都可能不同。“区域加载顺序”设置决定这些区域在界面里
（添加区域的弹窗、区域列表、加载进度）和实际载入时的顺序。

| 设置 | 含义 |
| --- | --- |
| 文件顺序 | 按文件给出的顺序，可能每次载入都不一样；这是原来的行为。 |
| 自然顺序 | 按名称排序，名称里的数字按数值比较：`2` 在 `10` 前面。 |
| 自定义规则 | 按下面的通配符规则排序。 |

## 自定义规则写法

规则是一组用逗号或分号分隔的通配符模式。每个区域名**按顺序**与这些模式比较，
第一个匹配的模式决定它属于哪一组，组号小的排在前面；同一组内仍按自然顺序。

- `*` 匹配任意长度（包括零）的字符。
- `?` 匹配恰好一个字符。
- 区分大小写；只匹配区域名本身，不包含文件扩展名。
- 没有匹配任何模式的区域会保留，按自然顺序排在已匹配的区域之后，所以规则不会丢
  掉区域。
- 规则为空，或没有任何可用模式时，按自然顺序处理。

## 例子

假设区域名是 `1a`、`2b`、`10c`、`part2`、`part10`：

| 规则 | 结果 |
| --- | --- |
| `2*, 1*` | `2b`、`1a`、`10c`、`part2`、`part10` |
| `part*` | `part2`、`part10`、`1a`、`2b`、`10c` |
| `part1*, part2*` | `part10`、`part2`、`1a`、`2b`、`10c` |
| `*rail*` | 名称里含 "rail" 的排前面，其余随后 |
| `?-?` | `a-1` 这样的名称排前面，其余随后 |

## 试一试

设置里这一行右边有 **预览...** 按钮：它会列出示例区域名（默认是最近打开的多区域
文件里的区域，没有就放一个小例子），并在你修改规则时立即显示排序结果，这样不用
真的载入文件就能检查规则。添加区域的弹窗也有同样的顺序控件，改动时列表会立即重排。
